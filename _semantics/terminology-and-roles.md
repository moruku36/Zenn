# 用語・記事ステータス定義書

記事(articles/)を書く・直す前に読む「名詞」の台帳。手順は docs/disciplines/ に置く。

> 優先順位: この辞書と一次記録(各記事の frontmatter、対象リポジトリの記録、請求・計測の原本)が食い違った場合は、一次記録を上位の正とし、この辞書を直す。

## 1. 記事の公開ステータス

| 用語 | 定義(一次ソース: 記事の frontmatter) | 書き方 |
| --- | --- | --- |
| 公開 | `published: true` | 「公開済み」と書いてよい |
| 下書き | `published: false` | 「下書き」と書き、公開済みと書かない |
| 公開予約 | `published: true` かつ `published_at` が未来日時(例: `articles/aidb-meetup-ai-cybersecurity-2026.md` は 2026-10-23 18:00 で、2026-10-29 時点では過去日時) | 未来日時の間は「公開予約」と書く。Zenn側の予約仕様は公式ドキュメントで未確認 |

frontmatter の `published` が `True` や `ture` などの表記ゆれで書かれた記事が存在する。Zenn が公開と解釈するかは未確認なので、記載を直すときは `true` / `false` に揃えるか、直さずに報告する。

## 2. 事実・観測・推測の3区分

| 区分 | 定義 | 書き方 |
| --- | --- | --- |
| 事実(公開資料) | 公式発表・公式ドキュメント・公開リポジトリで裏付けられる内容 | 出典URLを添える |
| 観測(実測値) | 筆者の環境・特定コミット・特定日時に実際に測定・確認した値 | 計測日・対象コミット・環境を添える |
| 推測(未確認) | 解釈、または未検証の領域 | 「推測」「未確認」と明記する |
