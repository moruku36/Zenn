## 1. はじめに

LLM の API を試そうとすると、2つの不安が先に立ちます。

> - 無料枠で触っているつもりが、いつの間にか課金されていないか
> - 入力した文章が学習に使われないか

さくらの AI Engine は、この2点に公式の答えを用意しています。入力データを学習・保存しない方針（ZDR）と、月3,000リクエストまでの無償プランです。

本記事では、無償プランの Playground で3モデルに同じ3課題を解かせ、回答を目視と独立計算で照合した結果をまとめます。検証は2026年11月6日に行いました。

## 2. 主な機能

公式ページで確認した無償プランの条件は次のとおりです。

> - Chat Completions は月3,000リクエストまで無料。超過時はレート制限され、自動課金はありません
> - 入力データは学習・保存されません（ZDR）。処理は国内データセンターです
> - Chat Completions の掲載は10モデル。うち Weblab-MedLLM は無償枠の対象外なので、無償で触れるのは9モデルです
> - RAG は無償枠の対象外で、3円／100チャンクの従量課金です

### よくある勘違い

無償プランは「全部無料」ではありません。RAG と MedLLM は対象外です。試す前に、対象範囲を確認する必要があります。

## 3. 検証方法

Playground で、空の会話から各1回だけ送信しました。再試行は0回です。対象モデルと課題は次のとおりです。

```
モデル: gpt-oss-120b / llm-jp-3.1-8x13b-instruct4 / preview/Kimi-K2.6
課題1（説明）: RAGの仕組み・利点・注意点を非専門家向けに450字以内で
課題2（コード）: Python関数 moving_average(values, window) と unittest を提示。
                [2,4,6,8,10] の window=4 と 5 の期待値は、部分列から独立に計算すること
課題3（要約）: 公共施設の省エネ施策の文章を、原文にない数値を加えず箇条書き3項目で
設定: Playground の既定設定（temperature 等の一致は未確認）
```

生成コードは実行していません。テストの期待値は、モデルとは別に手計算して照合しました。TTFT とトークン数は未計測です。

### よくある勘違い

モデル自身が書いた「根拠」や手計算は、検証の代わりにはなりません。今回も、もっともらしい説明と一緒に誤った期待値を正当化した例がありました。

## 4. 結果

### 4.1 説明（RAG）

3モデルとも、検索と生成の役割分担と「参照があっても正しさは保証されない」ことに触れました。

Kimi-K2.6 は3区分で簡潔にまとめ、「資料自体が誤っている場合」と「AI が誤って解釈・組み合わせる場合」を分けて書きました。gpt-oss-120b も出典確認の方法まで含みましたが、「リアルタイムで取り込めるため網羅的になる」という表現は条件を省いた強めの言い方です。

llm-jp-3.1-8x13b-instruct4 は、450字の指示を大幅に超える長い段落で返しました。内容は大きく外れていませんが、指示した形式と長さは守られていません。

### 4.2 コード生成

照合に使った正解は次のとおりです。

```
[2,4,6,8,10], window=4 → [5, 7]   （(2+4+6+8)/4=5, (4+6+8+10)/4=7）
[2,4,6,8,10], window=5 → [6]
```

gpt-oss-120b と Kimi-K2.6 は、関数・テスト・期待値が独立計算と一致しました。Kimi-K2.6 は入力を変更しないことのテストを含む10件のテストを提示しています。

一方、llm-jp-3.1-8x13b-instruct4 の関数は目視では仕様に沿っていましたが、テストの期待値を複数誤りました。

> - window=4 の期待値を [5, 6, 7, 8, 9] とした（正解は [5, 7]）
> - window=5 の期待値を [4, 6, 8, 10] とし、別行では [6, 8, 10] とも書いた（正解は [6]）
> - 説明文でも誤った値を正しいものとして解説した

入力不変のテストも欠けていました。なお、生成コードは実行していないため、ここで分かるのは期待値の正誤までです。

### 4.3 要約

原文の9要素（施設数、使用量と内訳、対策、削減率、室温の課題、継続測定、事業費、回収未確定、一般化への留保）で照合しました。

Kimi-K2.6 は正確な3箇条書きで、9要素を保持し、原文にない数値を足しませんでした。

gpt-oss-120b は9要素を保持しましたが、原文にない 66万／36万／18万kWh を追加しました。計算自体は合っています。ただし「数値を加えない」という指示には反します。

llm-jp-3.1-8x13b-instruct4 は箇条書きではなく一段落で返し、「暑い日」という条件などを落としました。

### よくある勘違い

各モデル・各課題とも1回だけの実施です。今回の結果は**順位**ではなく、モデルごとの癖の具体例として読んでください。

## 5. 考察と過去の記録

過去の記録では、同日に行った別ラウンド（9モデル×3課題、27件）でも似た癖が見えています。

> - 要約で「一般化しない」を「一般化する」と意味を反転させたモデルがあった
> - 施設の比率を取り違えて対応付けたモデルがあった
> - 生成テストの期待値が全て誤っていた小規模モデルがあった（実行証跡があるのは旧 Qwen の関数1入力のみ）

今回と過去を合わせると、弱点は文章の流暢さではなく、数値と意味の**忠実さ**に寄っています。期待値と要約は、別系統で照合して初めて業務に使えます。

## 6. 注意点

> - API 検証は未実施です。OpenAI 互換／Anthropic 互換 API の疎通と Claude Code 連携の確認はこれから行います
> - 生成コードは実行していません。「動いた」「テスト合格」とは書けません
> - TTFT・トークン数は未計測です。速度の比較もしていません
> - 試験後の利用表示は37回・0円でした。ただし実送信9件との差が+7あり、この0円は利用表示上の観測で、確定した請求ではありません
> - 検証した1モデルは preview 扱いで、予告なく提供終了や仕様変更がありえます

## 7. まとめ

無償プランの範囲でも、9モデルを課金の心配なく触れます。ZDR の明記と合わせて、試用の入口としては条件がそろっています。

一方で、回答の質は課題ごとに癖があります。今回の範囲では、要約と期待値の照合を省くと、そのまま誤りを業務に持ち込む結果になりました。
